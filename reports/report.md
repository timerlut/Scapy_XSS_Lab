# Отчёт по практической работе

## Анализ сетевого трафика с помощью Scapy и исследование XSS-уязвимости

## 1. Цель и задачи практической работы

**Цель работы** — изучение возможностей библиотеки Scapy для перехвата и анализа сетевого трафика, исследование структуры HTTP-запросов и ответов, а также изучение механизмов передачи и обработки потенциально опасных пользовательских данных в веб-приложении.

Для достижения поставленной цели были определены следующие задачи:

- изучить структуру HTTP-запросов и ответов;
- настроить окружение для захвата сетевого трафика с помощью Scapy;
- организовать перехват TCP-пакетов, содержащих HTTP-трафик;
- исследовать HTTP GET- и POST-запросы;
- проанализировать HTTP-заголовки, параметры URL и тело POST-запросов;
- изучить передачу пользовательских данных на сервер;
- исследовать обработку HTML и потенциально опасных XSS-конструкций;
- сохранить захваченный трафик в формате PCAP;
- выполнить анализ сохранённых пакетов и сформулировать выводы.

## 2. Используемые инструменты и среда

В ходе практической работы использовались следующие инструменты:

| Инструмент | Назначение |
|---|---|
| Windows | Операционная система |
| Python 3.9.13 | Язык программирования |
| Scapy 2.8.0 | Захват и анализ сетевых пакетов |
| Npcap | Драйвер захвата сетевого трафика |
| PowerShell | Запуск команд и Python-скриптов |
| Веб-браузер | Взаимодействие с тестовым сервером |

Для изоляции зависимостей использовалось виртуальное окружение Python `venv`.

Основная библиотека проекта — Scapy. Она применялась для перехвата сетевых пакетов, сохранения результатов в PCAP и последующего анализа.

Основные файлы проекта:

- `post_test_server.py` — локальный HTTP-сервер;

- `test_capture.py` — вспомогательный скрипт тестирования захвата;
- `test_scapy.py` — вспомогательный скрипт проверки Scapy.

## 3. Описание экспериментального стенда

Для проведения экспериментов был разработан собственный локальный HTTP-сервер на основе стандартных средств Python.

Сервер реализован с использованием классов `HTTPServer` и `BaseHTTPRequestHandler`.

Адрес тестового сервера:

`http://127.0.0.1:8009`

Сервер предоставляет HTML-форму, позволяющую отправлять пользовательские данные методом POST.

Форма содержит два поля:

- `name` — имя пользователя;
- `message` — текст сообщения.

После отправки формы браузер формирует HTTP POST-запрос к обработчику `/submit`.

Сервер выполняет следующие действия:

1. Получает длину тела запроса из заголовка `Content-Length`.
2. Считывает тело HTTP-запроса.
3. Декодирует полученные данные в UTF-8.
4. Разбирает параметры формы с помощью `parse_qs`.
5. Извлекает значения параметров `name` и `message`.
6. Формирует HTML-ответ с результатами обработки.

Для предотвращения непосредственной вставки пользовательского HTML сервер применяет функцию `html.escape()` к полученным значениям.

После обработки данных сервер возвращает ответ с кодом `200 OK`.

Таким образом, экспериментальный стенд позволяет исследовать передачу данных по HTTP и поведение сервера при обработке пользовательского ввода.

## 4. Методика захвата HTTP-трафика с помощью Scapy

Для перехвата сетевого трафика использовалась библиотека Scapy.

Захват выполнялся на локальном сетевом интерфейсе с фильтрацией TCP-пакетов по порту тестового сервера.

Используемый BPF-фильтр:

`tcp port 8009`

Для организации эксперимента применялся разработанный скрипт `scapy_analyzer.py`, поддерживающий два режима работы:

- `capture` — захват сетевых пакетов и сохранение их в PCAP;
- `analyze` — чтение и анализ ранее сохранённого PCAP-файла.

Пример использованной команды захвата POST-трафика:

```powershell
python .\scapy_analyzer.py capture --timeout 40 --filter "tcp port 8009" --output test_post.pcap
```

После выполнения захвата полученные пакеты сохранялись в файл `test_post.pcap`.

Для последующего исследования применялся режим анализа:

```powershell
python .\scapy_analyzer.py analyze --input .\test_post.pcap
```

Сохранение трафика в формате PCAP позволило повторно исследовать сетевое взаимодействие без необходимости повторного выполнения запросов в браузере.

## 5. Анализ HTTP GET- и POST-запросов

### 5.1. Анализ HTTP GET

Первоначально было исследовано обращение браузера к главной странице локального сервера.

При открытии адреса `http://127.0.0.1:8009` браузер отправляет GET-запрос:

```http
GET / HTTP/1.1
Host: 127.0.0.1:8009
```

В результате сервер возвращает HTML-страницу с формой ввода пользовательских данных.

В захваченном трафике `test_post.pcap` также присутствовали обращения к ресурсу `/favicon.ico`.

Таким образом, GET-запрос использовался для получения HTML-страницы и отображения формы в браузере.

### 5.2. Анализ HTTP POST

Для исследования передачи пользовательских данных была заполнена форма на локальном сервере.

В ходе эксперимента использовались следующие значения:

- Имя: `Yana`
- Сообщение: `Hello Scapy`

После отправки формы браузер сформировал запрос:

```http
POST /submit HTTP/1.1
Host: 127.0.0.1:8009
Content-Type: application/x-www-form-urlencoded
```

Тело запроса:

```text
name=Yana&message=Hello+Scapy
```

В запросе использовался формат `application/x-www-form-urlencoded`.

Пробел между словами в параметре `message` был представлен символом `+`.

При анализе захваченного трафика были обнаружены следующие данные:

| Параметр | Значение |
|---|---|
| Метод | POST |
| Путь | `/submit` |
| Host | `127.0.0.1:8009` |
| Content-Type | `application/x-www-form-urlencoded` |
| name | `Yana` |
| message | `Hello Scapy` |

В заголовках запроса также присутствовали `Content-Length`, `Origin` и `Referer`.

В результате анализа файла `test_post.pcap` было обнаружено 47 пакетов.

Таким образом, эксперимент подтвердил возможность перехвата и исследования HTTP POST-запросов, включая анализ передаваемых в теле запроса пользовательских данных.

## 6. Анализ HTTP-ответов сервера

После получения POST-запроса сервер выполняет обработку переданных параметров и формирует HTML-страницу с результатами.

В захваченном трафике был обнаружен ответ:

```http
HTTP/1.0 200 OK
Content-Type: text/html; charset=utf-8
```

В теле ответа присутствовали следующие данные:

```text
Данные получены
Имя: Yana
Сообщение: Hello Scapy
```

Таким образом, сервер успешно обработал переданные значения и вернул браузеру результат.

Важной особенностью реализации является использование `html.escape()` перед вставкой пользовательских данных в HTML.

Это позволяет преобразовать специальные HTML-символы в безопасные HTML-сущности и предотвратить непосредственную интерпретацию пользовательского ввода как HTML-разметки.

## 7. Исследование XSS и обработки пользовательских данных

### 7.1. Цель исследования

Дополнительная часть эксперимента была посвящена изучению межсайтового выполнения сценариев (Cross-Site Scripting, XSS).

XSS возникает в случаях, когда веб-приложение небезопасно обрабатывает пользовательские данные и допускает их интерпретацию браузером в качестве HTML-разметки или JavaScript-кода.

В рамках исследования рассматривалась передача потенциально опасных строк через HTTP и обработка полученных значений сервером.

### 7.2. Обработка потенциально опасного HTML

В реализации собственного HTTP-сервера предусмотрено экранирование пользовательских данных с помощью функции:

```python
html.escape()
```

Функция применяется к значениям перед формированием HTML-ответа.

Поэтому наличие HTML-тегов или JavaScript-конструкций во входных данных само по себе не означает успешное выполнение XSS.

При анализе необходимо различать три этапа:

1. Передачу тестовой строки в HTTP-запросе.
2. Получение и обработку строки сервером.
3. Отображение результата браузером и возможное выполнение JavaScript.

### 7.3. Результаты исследования

В ходе работы изучалась передача тестовых данных через HTTP и их отображение в браузере.

Для собственного сервера подтверждена реализация механизма экранирования пользовательских значений.

При этом успешное выполнение JavaScript на собственном сервере имеющимися результатами не подтверждено.

Поэтому эксперимент не позволяет утверждать, что локальный сервер содержит XSS-уязвимость.

Для окончательного сравнения двух вариантов XSS-payload необходимо сопоставить исходные строки, содержимое захваченных запросов, HTML-ответы и фактическое поведение браузера.
